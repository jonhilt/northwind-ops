# renderfragment-across-render-modes repro (.NET 10)

A minimal .NET 10 Blazor Web App (pinned by `global.json` to SDK 10.0.102) with the guide's exact shape: a static SSR page `/warehouse` that wraps a "Queried at" stamp and a table in an interactive `<Collapsible @rendermode="InteractiveServer">` card. On .NET 10 the build is clean (no warnings), but the request fails with HTTP 500 and `InvalidOperationException: Cannot pass the parameter 'ChildContent' to component 'Collapsible' with rendermode 'InteractiveServerRenderMode'. This is because the parameter is of the delegate type 'Microsoft.AspNetCore.Components.RenderFragment', which is arbitrary code and cannot be serialized.`, thrown from `SSRRenderModeBoundary.ValidateParameters` during the static render. `/warehouse-interactive` is workaround 1 (`@rendermode InteractiveServer` on the whole page): it returns 200 and the card folds and reopens, but the whole page now lives on a circuit, and because the fragment's code re-runs there, the inline `DateTime.Now` stamp changes on every re-render (in .NET 11's captured snapshot it would not). Run `dotnet run --urls http://localhost:5354` here (prefix `ASPNETCORE_ENVIRONMENT=Development` to get the exception page instead of an empty 500), then `curl -i localhost:5354/warehouse`, or run `node probes/renderfragment-across-render-modes.mjs` from `tools/guide-shots` to drive both pages in Chromium.

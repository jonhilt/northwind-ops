# Repro: async "is this code taken?" validation on .NET 10

A trimmed .NET 10 Interactive Server Blazor app (pinned to SDK 10.0.102 by its own `global.json`) with a fake supplier "database" that already holds `EXOT-01` and answers lookups in 1.5 s. Page `/` is the guide's second workaround, an `async void` `EditContext.OnFieldChanged` handler. Type `EXOT-01`, Tab, and press Save at once: no pending state, Save stays enabled, `EditForm`'s synchronous `Validate()` passes, `OnValidSubmit` saves a duplicate `EXOT-01`, and "That code is already used." turns up 1.1 s *after* the save. Change the code twice quickly (`EXOT-01` then `ZZZZ-99`) and the stale answer for `EXOT-01` ends up on the free code, because nothing cancels the first lookup. Page `/sync-attribute` is the "just make it an attribute" option: `ValidationAttribute.IsValid` can only be synchronous, so it blocks on the lookup with `.GetAwaiter().GetResult()`, which deadlocks the circuit (the `Task.Delay` continuation needs the circuit's sync context): no message ever appears and the form stops responding. Run it with `ASPNETCORE_ENVIRONMENT=Development ASPNETCORE_URLS=http://localhost:5135 dotnet run`, then `node probes/async-form-validation.mjs` from `tools/guide-shots` (or click through by hand).

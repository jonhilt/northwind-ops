# label-and-input-ids: the .NET 10 problem

A one-page .NET 10 static-SSR Blazor app (`Components/Suppliers.razor`) with three supplier fields labelled the three ways you could in .NET 10, against a model that names them with `[Display]`. Field A uses a plain `<label>` next to `<InputText>`: InputText renders no `id` (`<input name="Input.Company">`), so clicking "Company name" focuses nothing and the input has no accessible name. Field B hand-types `for="supplier-emial"` / `id="supplier-email"` (one-letter typo): it builds with no warning, clicking the label focuses nothing, and the textbox is unnamed. Field C wraps the input, so focus works, but the typed label "Phone" has drifted from `[Display(Name = "Contact phone")]`, so posting the empty form shows the label "Phone" above "The Contact phone field is required." `Components/NoLabelYet.razor` shows that `<Label For>` does not exist yet: the build gives `warning RZ10012: Found markup element with unexpected name 'Label'` (a warning, not an error: it renders as a meaningless `<Label>` element). Run with `dotnet run --urls http://localhost:5334` in this folder (the local `global.json` pins SDK 10.0.102), then `node probes/label-and-input-ids.mjs` from `tools/guide-shots`, or `curl` the page and POST it empty to see the rendered markup and messages.

# virtualize-csp: .NET 10 repro (with a .NET 11 twin)

A one-page Interactive Server app: a 400px scroll box holding `<Virtualize Items="orders" ItemSize="40">` over 1000 rows, served by middleware with `Content-Security-Policy: style-src 'self'` (add `?csp=off` to drop the policy). The root app is pinned to .NET 10 (`global.json`, runtime 10.0.2); `net11/` is the identical source pinned to the .NET 11 preview 7 SDK. On .NET 10 with the policy, both spacers are rendered as `style="height: 39240px; flex-shrink: 0;"`, the browser refuses them (5 console errors: "Applying inline style violates the following Content Security Policy directive 'style-src 'self''"), each spacer measures 0px, the scroll box's scrollHeight is 760px instead of 40000px, and scrolling to the bottom stops at "Order #19": orders 20 to 1000 are unreachable, with no exception and nothing on screen to say why. With `?csp=off` the same .NET 10 page scrolls to "Order #1000". On .NET 11 with the policy the spacers render as `data-blazor-virtualize-reserved-height="38280"`, Blazor's script applies the height through `element.style` (so DevTools then also shows `style="flex-shrink: 0; height: 38280px; overflow-anchor: none;"`), scrollHeight is 40000px, the end shows orders 958 to 1000, and there are 0 CSP errors. Run: `ASPNETCORE_ENVIRONMENT=Development dotnet run --urls http://localhost:5674` here and `ASPNETCORE_ENVIRONMENT=Development dotnet run --urls http://localhost:5675` in `net11/`, then from `tools/guide-shots` run `node probes/virtualize-csp.mjs http://localhost:5674 http://localhost:5675` (it prints spacer markup, measured heights, scrollHeight, rendered rows before and after scrolling to the end, and CSP console errors, and saves `probes/virtualize-csp-net10.png` / `-net11.png`).

# supply-parameter-from-session: .NET 10 repro

A minimal .NET 10 (SDK 10.0.102, pinned by `global.json`) static SSR Blazor app showing the two workarounds the Field Guide entry describes, and how each one fails. `/hidden` carries a step-1 draft forward in hidden inputs: after step 1 posts `Packs[chai]=7`, step 2 shows "Ordering 7 packs", but a plain GET of the same page (refresh, or leave and come back) shows an empty step 1, and posting Send with the hidden input edited to 9999 is accepted ("SENT: 9999 packs of chai"). `/manual` reads and writes `HttpContext.Session` by hand with `JsonSerializer`; when the handler calls `Save()` the review page shows `{"chai":7}`, but `/manual-forgot` (the same handler minus the `Save()` call) also returns 302 to the review page, which says "There's no draft in session.", with no exception or log warning and no `.AspNetCore.Session` cookie issued. Adding `[SupplyParameterFromSession]` to a .NET 10 component fails with CS0246, since the attribute is new in .NET 11. Run `./run.sh` (it builds, starts the app on http://localhost:5129, drives every case with curl, prints the results and stops the server).

# virtualize-anchor-mode repro (.NET 10)

Shows what a live feed does with .NET 10's `Virtualize`, which has no `AnchorMode`. `/` is a plain `<Virtualize Items="messages">` in a 300px scroller with 50px rows: scroll to the bottom, click **Add message**, and the new message lands below the fold (the probe measured the gap below the viewport going 0 → 51 → 102 → 153px while the last visible row stayed at #29). `/js-workaround` is the entry's "track the bottom with JavaScript" workaround (`chat.isAtBottom` before adding, `chat.scrollToBottom` after) over 300 rows of mixed height: it follows for three adds, then a tall row arrives, the jump lands 72px short, `isAtBottom` returns false from then on, and the feed stops following for good (gap 103, then 135px). `/try-anchormode` holds the .NET 11 syntax. `dotnet build -p:TryAnchor=true` compiles it on .NET 10 with **no error or warning**, because Razor passes `"VirtualizeAnchorMode.End"` as a string attribute. Requesting the page then returns HTTP 500 with `InvalidOperationException: Object of type 'Virtualize`1[...]' does not have a property matching the name 'AnchorMode'`. To run it, start `ASPNETCORE_ENVIRONMENT=Development dotnet run --urls http://localhost:5549` in this folder (the local global.json pins SDK 10.0.102), then run `node probes/virtualize-anchor-mode.mjs` from `tools/guide-shots`.

# QuickGrid sort/page on .NET 10 (repro for `quickgrid-url-paging`)

This repro pins SDK 10.0.102 and QuickGrid 10.0.2. It renders the same 25-row grid (`Components/ProductGrid.razor`, the guide's Workaround 1 markup: `Sortable="true"` columns plus a `<Paginator>`) on two pages: `/static` (no render mode) and `/interactive` (`@rendermode InteractiveServer`). On `/static` the headers and pager render as `<button type="button">` with no handler, so clicking Price or "next page" does nothing (no error, no request), and `?sort=Price&direction=desc&page=2` in the URL is ignored. On `/interactive` the clicks work (a WebSocket circuit opens), but the URL never changes. A refresh, or opening a URL that carries `sort`/`direction`/`page`, lands back on page 1 sorted by Product. Run it with `ASPNETCORE_ENVIRONMENT=Development dotnet run --urls http://localhost:5522` (Development is needed so `blazor.web.js` is served from static web assets). Then from `tools/guide-shots` run `node probes/quickgrid-url-paging.mjs`, or run `curl -s localhost:5522/static | grep -o '<button[^>]*>'` to see the dead buttons.

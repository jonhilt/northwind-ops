# circuit-auto-pause repro (.NET 10)

A minimal .NET 10 Interactive Server app (pinned by `global.json` to SDK 10.0.102) showing the two problems .NET 11's AutoPause package addresses. One page (`/`) has a `[PersistentState]` count and note bound with `@bind`, a plain field stamped when the component is created, and the circuit id. `GET /circuits` returns how many circuits the server holds (a `CircuitHandler` counts opens and closes). Without a script, a tab that stays hidden keeps its circuit: in scenario A the count stays at `open: 1` for the full 20 s it is hidden. With `?diy=1` the page loads the .NET 10 workaround from the guide (`wwwroot/diy-pause.js`, the same `visibilitychange` + `Blazor.pauseCircuit()` script, with a 3 s delay instead of 120 s). Scenario B: the circuit is freed about 3 s after the tab hides and comes back on a new circuit id, with the count and note restored and the plain field created again. Scenario C: the user leaves the cursor in a half-typed note. The script pauses anyway, so the text that never reached the server (`", and the chai pallet is"`) is gone after resume. The input shows only the last value committed on blur. To run it: `ASPNETCORE_ENVIRONMENT=Development dotnet run --urls http://localhost:5128` here (Development is needed so `blazor.web.js` is served from the build output), then `node probes/circuit-auto-pause.mjs` from `tools/guide-shots`. Headless Chromium never hides a tab, so the probe overrides `document.visibilityState` and fires `visibilitychange`. Note that `ctx.close()` only disconnects a circuit: the server keeps it for the disconnected-circuit retention period (3 min by default), so `open` climbs across scenarios.

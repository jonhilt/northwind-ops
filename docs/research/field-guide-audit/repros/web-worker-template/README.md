# Repro: CPU-heavy C# freezes a .NET 10 Blazor WebAssembly page

A trimmed .NET 10 standalone Blazor WebAssembly app (pinned to SDK 10.0.102 by its own `global.json`) that builds 300,000 order lines as a 12.5 MB CSV in the browser (same columns as the guide demo: OrderId,OrderDate,CustomerId,Product,UnitPrice,Quantity,Discount) and totals revenue by product. A clock on the page ticks every 100 ms from a .NET timer, and after each run the status line says how many times it actually ticked against how many it should have. **Total on the UI thread** freezes the page: in our run it took 7.9 s, the clock ticked 0 times (expected about 79), and the browser drew no frame for 7,921 ms. **Total, with Task.Delay(1) every 1,000 lines** (the guide's first workaround) keeps the page alive (92 of 92 ticks, longest frame gap 48 ms) but runs about 17% slower (9.2 s) and the pause has to be threaded into every heavy loop. Nothing here is broken in .NET 10: running .NET in a Web Worker was already possible by hand (Microsoft's .NET 10 docs article); .NET 11 adds the `blazorwebworker` template that scaffolds it. Run it with `dotnet run -c Release` (serves http://localhost:5134), then `node probes/web-worker-template.mjs` from `tools/guide-shots` (set `SHOT=/tmp/wwt` to save screenshots), or click the buttons and watch the clock.

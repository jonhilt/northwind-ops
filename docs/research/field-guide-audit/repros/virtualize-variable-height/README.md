# virtualize-variable-height repro (.NET 10)

A minimal .NET 10 Interactive Server Blazor app (pinned by `global.json` to SDK 10.0.102) with the same markup as the guide's .NET 11 demo: a `<Virtualize Items="messages" ItemSize="80">` over 420 messages in a 440px scrolling box, where every third message is a long email clamped to three lines (Show more / Expand all) and the rest are one-line sync-bot log entries. On .NET 10 it fails in two ways you can measure. While scrolling, the scrollbar jumps: `Virtualize` resizes its spacers from the average height of the dozen items rendered *right now*, so the container's `scrollHeight` swung between 33,057 and 45,607px over 40 steady 400px scroll steps, and the top message went *backwards* 10 times while scrolling down. When you expand, the content moves: `Virtualize.ts` sets `overflow-anchor: none` on the container, so pressing Expand all while reading message #127 pushed it down 549px, because the two long messages rendered just above the viewport (#123, #126) grew. The same files built for net11.0 (SDK 11 preview 7) gave a steady `scrollHeight` (34,115 to 35,067px, top message never went backwards) and the message being read moved by 1px (`scrollTop` corrected by 1,371px). To run it, use `dotnet run --urls http://localhost:5126` here, then `node probes/virtualize-variable-height.mjs http://localhost:5126 net10` from `tools/guide-shots` (it scrolls, jumps to 50%, presses Expand all and prints the numbers). Or just open the page, drag the scrollbar slowly and watch the thumb resize and jump, then scroll to the middle and press Expand all.

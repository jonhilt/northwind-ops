# virtualize-scroll-to-item (.NET 10 repro)

A .NET 10 Interactive Server app with one 500-message thread (one-line log entries, with a 12-line "email" every 5th message) shown in a 400px `Virtualize` box. It shows that you can't open a virtualized list at `?message=240` or jump to a message from code. `/offset?message=240` scrolls to `(n-1)*120px` with JS and lands on #241, with #240 267px above the top. `/jump` uses the same maths for "Go to #35" and lands on #46, with #35 not in the DOM. `/byid?message=240` calls `scrollIntoView` and finds nothing, because only #1-#12 are in the DOM. `/all?message=240` drops virtualization and lands exactly, but puts all 500 articles in the DOM. In .NET 10 the prerendered HTML for a `Virtualize` holds no items at all, only a 60000px spacer. `/newapi` uses the .NET 11 `InitialItemIndex`: it compiles with no warning, then returns HTTP 500 at runtime with "does not have a property matching the name 'InitialItemIndex'". Calling `ScrollToItemAsync` doesn't compile (CS1061). To run it: `ASPNETCORE_ENVIRONMENT=Development dotnet run --urls http://localhost:5851` here (Development is needed so `blazor.web.js` is served from the static web assets manifest), then `node probes/virtualize-scroll-to-item.mjs` from `tools/guide-shots`.

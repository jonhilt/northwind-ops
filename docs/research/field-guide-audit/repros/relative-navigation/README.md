# relative-navigation repro (.NET 10)

A minimal .NET 10 static-SSR Blazor app (pinned by `global.json` to SDK 10.0.102, `<base href="/">` as in the template) showing what a "sibling" link does before `RelativeToCurrentUri` existed. `/orders/{id}/{tab?}` renders three tab strips: bare `NavLink href="lines"` tabs (the natural way to write them), the spell-out-the-path workaround (`href="orders/{Id}/lines"`, so the tabs need the id), and a look-alike `NavLink href="lines" RelativeToCurrentUri="true"`, which compiles in .NET 10 because NavLink captures unknown attributes and just renders `RelativeToCurrentUri="true"` into the HTML. Visiting `/orders/11077` calls `NavigateTo("summary")`, which answers `302 Location: /summary` (a 404), not `/orders/11077/summary`; on `/orders/11077/summary` the bare tabs resolve to `/summary`, `/lines`, `/customer` (none marked active), and clicking Lines lands on `/lines` with "404 Not found", while the full-path tabs work. Run `dotnet run --urls http://localhost:5277` here, then `./probe.sh` (curl: redirect header and rendered hrefs) or `node probes/relative-navigation.mjs` from `tools/guide-shots` (Playwright: clicks each Lines tab with enhanced navigation on and prints where it lands). `dotnet build -p:TryNet11Api=true` compiles `Probe/Net11Api.razor` and fails with CS0117 "'NavigationOptions' does not contain a definition for 'RelativeToCurrentUri'", confirming the API is new in .NET 11.

# wasm-culture-from-server repro (.NET 10)

A minimal Blazor Web App (server `CultureRepro` + client `CultureRepro.Client`, pinned by `global.json` to SDK 10.0.102) whose static SSR home page sets its culture from `?culture=` via request localization (with `AddLocalization()` registered) and renders two prerendered `InteractiveWebAssembly` components that format 1234.56 with `"N2"` and 13 Nov 2026 with `"D"`: `Invoice` uses the current culture, `InvoiceWithCulture` is the ".NET 10 workaround 2" (culture name passed as a parameter and used in the total's `ToString`, but deliberately forgotten on the date). On .NET 10, `/?culture=de-DE` is served as `1.234,56` / `Freitag, 13. November 2026`, then the moment WebAssembly takes over, the plain component flips to the browser's language (`en-US`: `1,234.56` / `Friday, November 13, 2026`; `fr-FR` browser: `1 234,56` / `vendredi 13 novembre 2026`), and the parameter component keeps its total German but its date flips. Adding `&fix=start` switches `App.razor` to the ".NET 10 workaround 1" (`autostart="false"` + `Blazor.start({ webAssembly: { applicationCulture } })`), and then both stay German. Run `ASPNETCORE_ENVIRONMENT=Development dotnet run --project CultureRepro --urls http://localhost:5262` here, then `node probes/wasm-culture-from-server.mjs` from `tools/guide-shots` to print each line as prerendered and after WebAssembly starts, for an en-US and a fr-FR browser.

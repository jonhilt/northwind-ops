# validation-localization: .NET 10 repro

Shows that in .NET 10 (SDK 10.0.102, pinned by `global.json`) Blazor's validation never asks an `IStringLocalizer` for a message. The app has `AddLocalization()`, `AddValidation()`, `[ValidatableType]`, a registered localizer that holds `RequiredAttribute_Error`, and a request culture of de-DE. Even so, form A (plain attributes, the .NET 11 style) renders "The Firma field is required." and "The E-Mail field is not a valid e-mail address." in English. Form B uses the .NET 10 workaround (`ErrorMessageResourceType`/`ErrorMessageResourceName` on each attribute) but leaves the settings off `[EmailAddress]`. It renders a mix: "Firma ist ein Pflichtfeld." next to "The E-Mail field is not a valid e-mail address.". In .NET 10, `ValidationOptions` has only `Resolvers` and `MaxDepth` and no `LocalizerProvider`, so the .NET 11 wiring line won't compile. To run it, start the app with `dotnet run --urls http://localhost:5101`. GET `/suppliers/new?culture=de-DE` to get the antiforgery cookie and token. Then POST to the same URL with `_handler=plain`, `A.Company=` and `A.Email=sales@` (or `_handler=resource` with the `B.*` fields), and grep the response for `validation-message`.

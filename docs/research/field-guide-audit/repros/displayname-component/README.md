# displayname-component: .NET 10 repro

A static SSR Blazor app on .NET 10 (pinned by `global.json` to SDK 10.0.102) where one model, `SupplierForm`, carries `[Display(Name = ...)]` names and the team has just renamed "Main contact" to "Contact person". The page shows the four places those names should appear: (1) the form's validation messages, which DataAnnotations builds from `[Display]` and so say "The Contact person field is required."; (2) table headers typed by hand, which still say "Main contact" (the drift); (3) a QuickGrid `PropertyColumn` with no `Title`, which ignores `[Display]` and prints the raw property names "Code", "Company", "Contact"; and (4) the .NET 11 `<DisplayName For>` markup, which on .NET 10 builds with three `RZ10012: Found markup element with unexpected name 'DisplayName'` warnings and renders as an empty, unknown `<DisplayName>` HTML element, so the headers are blank. Run it with `dotnet run --urls http://localhost:5199`, open http://localhost:5199/, then press Save with the fields empty to see the validation messages beside the stale headers (or `dotnet build --no-incremental` to see the warnings).
